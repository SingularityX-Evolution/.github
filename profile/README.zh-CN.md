## 我们正在探索

我们以 AI4S → RSI → AI4S 为研究路径：以人工智能推动科学研究，通过研究改进智能系统，再将更强的智能投入新的探索，让科学发现与递归自我改进相互促进。

金融市场是我们的起点。面对高度非平稳、强对抗、充满不确定性的真实环境，我们的研究不止于“更好的预测模型”，而是进一步追问：智能体如何在变化中保持决策的可靠性？策略如何在多智能体协作与博弈中生成、接受验证、参与竞争并持续演化？系统又如何改进产生策略的方法，而不只是优化某一条策略？

我们希望逐步从“人类设计策略、机器执行策略”，走向“人类定义问题、目标与边界，系统自主提出假设、开展实验、验证并迭代策略”的人机协同研究方式。自主性的提升，必须伴随独立验证、AI 攻防、可追溯决策与风险控制能力的同步提升。

我们也在探索与这一技术路径相匹配的组织方式：通过开放问题、模块化协作、贡献记录、价值评估与可解释、可申诉的分配机制，让提出关键问题、构建公共基础设施、发现错误、验证假设和创造长期价值的人，都有机会获得与贡献相匹配的回报。技术能够扩大共同创造的成果，公平分配则需要被认真设计。

从金融智能决策出发，我们长期关注科学研究、人机共同学习，以及人工智能与神经科学交叉的可能性。坚持值得解决的问题，同时保持更换方法、修正判断和重新出发的能力。

让 Agent 稳定运行，是基础设施能力；让它更可靠地发现新知识，是研究能力；让它在可验证、可控制的边界内持续改进自身，是我们探索的演化能力。

## 如何提交挑战方案

以下解答提交流程仅适用于 `SX-CH-001` 至 `SX-CH-004`。金融研究问题征集按[问题征集规则](open-research/README.zh-CN.md)受理未解决的问题及前期思考或探索，不适用下列成果提交要求。

1. 阅读[挑战列表](challenge-board/README.zh-CN.md)、具体题面和[最新档位状态](challenge-board/STATUS.zh-CN.md)。
2. 准备完整代码包、运行说明、复现命令、测试结果、环境信息、已知限制及权利声明。
3. 默认私密发送至 `join@singularityx.tech`，邮件标题使用：`[Challenge Submission] <Challenge ID> - <姓名>`；邮件正文必须附带 **本人真实姓名、有效联系方式和本人 GitHub 主页完整链接**（`https://github.com/<用户名>`）。联系方式至少提供一种常用邮箱、手机号码或微信；GitHub 主页为必填，不能用用户名、代码仓库链接、组织主页或他人主页代替。
4. 仅在主动选择公开代码和报告时使用公开 Pull Request；仍须通过上述邮箱提交三项必填信息并注明 PR 链接。不要公开私人联系方式、凭证、私有数据、账户信息或未公开策略。

**姓名、有效联系方式、本人 GitHub 主页链接三项均为必填，首次提交与升级提交同样适用。信息缺失、联系方式无效或主页链接不符合要求的，视为材料不完整，补齐前不进入正式评审。** 可直接使用[提交邮件模板](docs/challenge-submission-template.zh-CN.md)。

每位提交者对同一挑战有 1 次首次提交机会。对于 A 档仍开放的挑战，首次提交未达到 S 档但达到 A 档标准的，可正式认定为 A 档，并自 A 档认证确认邮件发出之时起 5 个自然日（120 小时）内，提交 1 个仅申请 S 档的完整升级版本，每人每题最多 2 次。A 档公告关闭后，后续提交只评定仍开放的档位，不再补充进行 A 档认定或等效核验；对于当前只开放 S 档的挑战，首次提交未达到 S 档标准的，不产生第二次提交机会。完整规则见[贡献指南](CONTRIBUTING.md)、对应题面及[最新档位状态](challenge-board/STATUS.zh-CN.md)。

**申诉与复核：** 申诉期为收到评审结果后 **5 个工作日**。主办方将在收到申诉后 **3 个工作日** 内回复。尚未完成复核的，主办方须在上述期限内说明当前进展及下一次反馈安排。修正评审自身错误或提出申诉，均不计为第二次提交。 详见[申诉规则](challenge-board/README.zh-CN.md#申诉与复核)。

## 价值评估与公平分配

我们希望组织中的长期贡献建立在可核实的证据和真实采用结果上，而不是由职位、表达能力、投入时长或单次结果决定。研究、数据、工程、验证、风险控制、文档、公共工具和协作支持都可以形成有效贡献；评估既关注个人完成了什么，也关注不同环节如何共同产生结果。

### 价值评估看什么

| 评估维度 | 关注内容 |
|---|---|
| 真实性与采用 | 贡献是否对应真实任务，是否被采用，并形成可验证结果。 |
| 质量与可信度 | 结果能否复现，证据是否完整，方法是否稳健，限制是否得到充分说明。 |
| 边际影响 | 与没有该贡献的情况相比，它实际增加了多少价值、降低了多少风险或不确定性。 |
| 长期影响 | 成果能否复用、维护、扩展并沉淀为组织资产。 |
| 风险与协作 | 是否遵守权限、合规和风险纪律，是否提高团队整体交付质量。 |

评估按照“贡献记录—证据核验—价值归因—人工复核”的流程进行。自述可以提供线索，但不能单独获得完整权重；重要结论需要代码、数据、实验、评审记录或实际采用结果支持。在适用场景下，可通过消融、反事实、滚动验证和受控对照辅助判断边际影响，但算法结果只作为复核依据，不替代最终判断。

### 公平分配如何实现

- **先明确分配边界：** 依据正式协议确定价值池、参与范围、结算条件和不可计入事项；公开挑战赏金与正式成员的长期贡献分开管理。
- **综合多种贡献依据：** 同时考虑直接交付、边际影响、反事实必要性、长期复用、风险控制和协作贡献，不以工时、头衔或单一评分直接决定结果。
- **重视共同成果：** 公共工具、基础设施、验证工作和团队协同应得到合理体现，避免只奖励最后可见的提交者。
- **保证总量守恒：** 分配不能超过已确认的价值池，同一成果不得重复计算，不确定或尚未成熟的部分可以暂缓确认。
- **保留复核与申诉：** 重大调整必须说明理由并披露利益冲突；相关成员可在适用窗口内提出复核。

这套机制的目标不是用一个分数替代判断，而是让判断有证据、分配有边界、调整有记录、结果可解释。

**详细框架：** [价值评估系统](docs/value-assessment-system.zh-CN.md) ｜ [价值分配协议](VALUE-DISTRIBUTION-PROTOCOL.zh-CN.md)

所有薪酬、奖金、分润、股权、期权、代币、积分或其他经济权益，以正式协议、适用法律、税务与组织审批结果为准。
