# 挑战代码提交模板

[English](challenge-submission-template.md) ｜ [返回首页](../README.zh-CN.md) ｜ [返回挑战列表](../challenge-board/README.zh-CN.md)

首次提交和每次升级提交代码时，邮件正文均必须附带以下三项本人信息：

| 必填项 | 填写要求 |
|---|---|
| 姓名 | 提交者本人真实姓名，不能仅填写昵称或 GitHub 用户名。 |
| 联系方式 | 至少一种常用且有效的联系方式，如邮箱、手机号码或微信；注明联系方式类型并确保可以及时联系。 |
| 本人 GitHub 主页链接 | 填写本人 GitHub 个人主页的完整、可访问链接，格式为 `https://github.com/<用户名>`。仅提供用户名、代码仓库链接、组织主页或他人主页不符合要求。 |

三项均为必填。信息缺失、联系方式无效或主页链接不符合要求的，视为材料不完整，补齐前不进入正式评审。完整材料送达时间按现有规则确定评审队列顺序。补齐上述身份与联系信息属于非实质性材料补充，不得借此新增或替换已提交的代码、实验结果或其他实质性评审材料。

## 邮件填写示例

收件人：`join@singularityx.tech`

邮件标题：`[Challenge Submission] <Challenge ID> - <姓名>`

复制以下正文，将所有占位内容替换为实际信息；代码包或代码仓库链接与个人主页链接分别填写。

```text
挑战编号：<例如 SX-CH-003；请先确认该挑战及申请档位仍开放>
提交类型：<首次提交 / 获准的 S 档升级提交>

姓名（必填）：<本人真实姓名>
联系方式（必填）：<邮箱 / 手机号码 / 微信：实际联系方式，至少一种>
本人 GitHub 主页链接（必填）：https://github.com/<本人用户名>

代码包附件 / 可访问的代码仓库链接：<附件名称或仓库地址>
提交版本：<commit hash 或压缩包 SHA256>
运行说明与复现命令：<说明或附件位置>
测试结果 / 评估报告：<说明或附件位置>
依赖环境、数据来源和授权说明：<说明或附件位置>
已知限制：<填写限制；无则注明无>
权利声明：本人拥有或已取得提交相关代码、数据及其他材料的必要权利。
公开 PR 链接（仅使用公开 PR 时填写）：<PR 地址>
```

具体技术交付物以所选题面为准，完整流程见[贡献指南](../CONTRIBUTING.md)。

## 选择公开 PR 时

公开 PR 提交同样必须通过上述邮箱提供姓名、有效联系方式和本人 GitHub 主页链接，并在邮件中注明挑战编号及 PR 链接，以便与代码对应。不要将手机号码、微信等私人联系信息写入公开 PR、Issue 或公开代码文件；一般公开提问无需填写这些个人信息。

提交这些信息用于提交者核验、评审联系及成果归属确认，不代表同意公开姓名、联系方式或关联展示 GitHub 主页。相关信息按[隐私政策](privacy-policy.zh-CN.md)处理。
