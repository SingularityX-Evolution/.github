# 价值评估公开框架

**规则解释主体：** 零界演化

本文件说明 SingularityX 正式成员的长期贡献如何被记录、验证、评价、归因、复核和审计。公开挑战赏金遵循具体挑战题面与评审规则；加入组织后的长期贡献评估，则重点关注真实采用、可验证影响、风险纪律、长期复用和协作价值。

本框架用于说明制度原则和公开方法，不构成任何固定薪酬、奖金、股权、Token 或其他经济权益承诺。具体安排以正式协议、适用法律和组织审批为准。

## 1. 基本原则

### 1.1 证据优先

没有可核实证据的贡献主张，可以被记录为线索，但不能直接进入正式价值归因。重要结论应由代码、数据、实验、评审记录、采用记录或其他可复核材料支持。

### 1.2 评价与价值相互区分

评价用于比较质量、形成解释和支持组织运行，需要清晰、稳定、可复算；价值可能来自协同、替代、时点、复用、风险控制和长期影响，具有非线性特征。单一评分不能完整代表真实价值。

### 1.3 算法辅助、人工负责

AI 和算法可以整理证据、识别差异、估计边际影响并生成解释，但最终分配、申诉处理、冲突仲裁、规则修订和责任认定必须由有权限的人类完成。

## 2. 评估对象

价值通常由多个环节共同产生，而不是只来自最后一次提交。公开框架会综合考虑：

| 环节 | 可能形成的贡献 |
|---|---|
| 数据与信息 | 数据获取、清洗、治理、质量检查和来源合规。 |
| 研究与建模 | 问题定义、假设、特征、模型、实验设计和结果解释。 |
| 工程与执行 | 代码、工具、平台、部署、执行、监控和维护。 |
| 验证与风险 | 独立验证、压力测试、风险预警、纠错和事故复盘。 |
| 知识与协作 | 文档、规范、评审、公共资产、经验沉淀和协作者支持。 |
| 人类判断 | 资源选择、风险边界、关键决策和责任承担。 |

因此，评估既看个人直接交付，也看不同贡献之间的依赖、复用和协同关系，避免只奖励最后可见的成果。

## 3. 公开分层框架

| 层级 | 名称 | 作用 |
|---|---|---|
| L0 | 协议与路由层 | 在任务开始前明确目标、角色、权限、交付物、验收标准、证据要求和申诉规则。 |
| L1 | 贡献记录层 | 将研究、代码、数据、验证、文档、风险处置和协作支持记录为可追踪贡献。 |
| L2 | 证据核验层 | 检查来源、时间、依赖、复现、独立评审、重复主张和利益冲突。 |
| L3 | 评价与归因层 | 形成可解释评价，并结合边际影响、反事实必要性、复用和协作关系进行价值归因。 |
| L4 | 权益映射层 | 将评估结果映射为适用协议约定的奖金权重、资源优先级、项目机会或其他激励参考。 |
| L5 | 结算与审计层 | 形成预结算、开放申诉、执行人工复核，并保留最终决定和更正记录。 |

## 4. 贡献记录与证据

一项重要贡献应记录：

- 贡献内容、参与人和适用任务；
- 发生时间、证据来源和验证状态；
- 上游依赖、下游使用和实际采用情况；
- 质量、复现、维护和长期复用情况；
- 独立评审、利益冲突和更正记录；
- 结果尚未成熟时的限制与不确定性。

系统同时关注传统产出统计容易忽略的贡献，例如提前发现风险、用证据推翻错误假设、重新定义问题、建设公共基础设施，以及帮助其他成员形成独立交付能力。

这些贡献同样需要证据和后续结果支持。反对次数、沟通数量、自我评价或作者自己的重复使用，不能单独形成较高贡献认定。

## 5. 价值评估维度

| 维度 | 公开口径 |
|---|---|
| 真实性与采用 | 是否解决真实问题，是否被采用，并产生可核实结果。 |
| 质量与可信度 | 是否可复现，证据是否完整，方法是否稳健，限制是否得到充分说明。 |
| 边际影响 | 与没有该贡献或使用合理替代方案相比，结果发生了多大变化。 |
| 风险调整 | 是否在创造结果的同时控制尾部风险、系统脆弱性、合规和执行风险。 |
| 长期复用 | 是否被独立使用、维护、扩展并沉淀为组织能力。 |
| 协作价值 | 是否提高团队交付、验证、决策或知识传递的整体质量。 |

投入时长、职位、代码行数、提交次数和表达能力可以作为背景信息，但不能单独决定价值。

## 6. 边际贡献与反事实

多人或多个模块共同产生结果时，系统会综合使用以下公开方法：

1. **边际贡献锚点：** 比较加入某项贡献前后，整体结果发生了什么变化。
2. **反事实必要性：** 判断没有该贡献或使用合理替代方案时，结果是否明显变差。
3. **长期复用影响：** 观察成果是否被其他成员、项目或流程独立采用并持续产生价值。
4. **协作稳定性：** 检查分配是否忽视了对结果至关重要的协作组合。
5. **质量与风险调整：** 对证据薄弱、复现不足、风险过高或规则问题未关闭的贡献进行降权、暂缓或复核。

在适用场景下，可以使用组件消融、受控对照、滚动验证和影子环境测试辅助分析。任何方法都应披露适用边界和不确定性，不把模型估计包装成确定事实。

## 7. 风险与长期价值

短期收益不是唯一价值标准。一个贡献即使提高了短期结果，如果同时显著增加尾部风险、回撤、执行成本、模型脆弱性或合规风险，也不能仅按表面收益获得正向认定。

相反，风险预警、独立验证、公共基础设施和长期维护即使没有直接产生可见收益，也可以在证据充分、实际采用和后续影响明确时形成长期贡献。

涉及避免损失时，应采用审慎的区间估计和独立复核，不把无法确认的最坏情形全部视为个人已经创造的价值。

## 8. 评估门禁

以下情况可以导致降权、暂缓或进入人工复核：

- 证据来源缺失、无法复现或与贡献主张不一致；
- 依赖关系、参与份额或实际采用情况无法确认；
- 同一成果、证据或复用被重复计算；
- 重大主张缺少独立评审；
- 权限、合规、知识产权或利益冲突问题尚未关闭；
- 结果尚未成熟、不确定性过高或申诉仍在处理中；
- 规则版本、评估记录或审计链不一致。

具体阈值、模型参数和评审设置由适用协议及受控规则版本管理，不作为长期固定承诺。

## 9. 两账本结构

| 账本 | 用途 | 特征 |
|---|---|---|
| 运行积分账本 | 支持任务路由、资源优先级、项目机会、评审资格和协作管理。 | 更新较快、强调可解释性，不直接等同于经济权益。 |
| 经济结算账本 | 支持额外贡献薪酬、奖金复核、长期激励评估或其他正式安排。 | 更新较慢，与真实采用、证据可信度、风险记录、申诉和审批绑定。 |

运行积分解决协作效率，经济结算解决正式分配。两者不能直接画等号。

## 10. 标准流程

    协议确认
    → 贡献登记
    → 证据核验
    → 质量评价
    → 边际与反事实归因
    → 风险和长期影响复核
    → 预结算
    → 申诉与独立复核
    → 最终审批
    → 形成可追踪证明

## 11. 人工调整与申诉

重大人工调整必须记录调整理由、证据、适用规则、审批人和利益冲突情况，并重新检查总量守恒。相关贡献者可以在适用窗口内提出补充证据或申请复核。

算法建议与人工判断存在明显差异时，应解释差异原因，而不是隐藏或自动覆盖其中一方。

## 12. Reward Proof

Reward Proof 的目标是让贡献者知道结果是什么、依据是什么、适用了哪一版规则，以及哪些部分仍处于复核或不确定状态。

可公开字段包括：

    reward_proof_id
    contribution_record_id
    evidence_summary_hash
    evaluation_round_id
    rule_version
    allocation_policy_hash
    settlement_period
    allocation_result
    review_status
    appeal_status
    correction_record
    timestamp

Reward Proof 是贡献评估与分配过程的证明记录，不是 Token、证券、股权、支付工具或固定现金价值。
